TraitTrack Guide

Collect. Collaborate. Track.

TraitTrack is a collaborative field-phenotyping application designed to help researchers collect, synchronize, manage, and review plant trait data directly during field experiments.

Get started →

What is TraitTrack?

TraitTrack is an iOS application for collecting structured phenotypic observations in the field. Observations are organized within shared projects rather than remaining isolated on individual devices.

📱

Field collection

Record trait observations directly against plots, entries, or other experimental units while working in the field.

👥

Collaboration

Multiple collaborators can contribute observations to the same project using their own devices.

☁️

Synchronization

Local observations can be synchronized with a shared project backend as connectivity becomes available.

📷

Rich observations

Observations can include photographs, location information, notes, and other project metadata.

What makes TraitTrack unique?

TraitTrack is built around the reality of collaborative field phenotyping: several people may be collecting data at the same time, connectivity may be unreliable, and project owners need to know what has been collected before the field season is over.

One shared project Multiple devices contribute to a common project rather than producing separate datasets that must be manually merged later.
Field-first data collection TraitTrack is designed around plot- and trait-level observations collected where the experiment is happening.
Near-real-time project awareness Project information can be synchronized between collaborators, allowing project owners to monitor collection while it is still underway.
Observation provenance Records retain information about the observation, contributor, experimental unit, trait, and relevant timestamps.
Images as project data Photographs can remain associated with the observation they document rather than existing as unrelated files in a device photo library.
Breeding-data interoperability TraitTrack supports BrAPI-based workflows so field observations can connect with broader breeding-data systems.
The central idea: TraitTrack treats field collection as a collaborative, continuously updated project rather than a collection of disconnected spreadsheets.

Getting Started

Set up TraitTrack, create the project structure, and give collaborators access before beginning field collection.

Installation

TraitTrack uses an iOS client for field collection and can connect to a shared cloud-based backend for collaborative project storage and synchronization.

iOS application

TraitTrack is designed for Apple devices running iOS 17.0 or later. The application is built with Swift and SwiftUI.

Release status: Installation instructions should be updated to reflect the current distribution method once the application is publicly released. Earlier development documentation described signed builds and TestFlight distribution.

Cloud-based collaboration

For collaborative projects, TraitTrack can use a dedicated backend consisting of a REST API and shared database. The documented server architecture uses FastAPI with PostgreSQL.

TraitTrack app

Installed on each collaborator's iOS device and used for field data collection.

Cloud API

Provides the shared interface through which devices exchange project and observation data.

PostgreSQL

Provides persistent storage for the collaborative project data.

Optional media storage

Server-based deployments can use Amazon S3 for photographs and other media attachments.

Google Drive

TraitTrack can also work with Google Drive as a shared storage provider. This is different from using a dedicated collaboration server for live reconciliation of concurrent changes.

Before field collection: Confirm that every device can access the intended project, that required project information is available locally, and that collaborators are signed into the correct accounts.

First Project

A TraitTrack project defines the experimental structure, traits, collaborators, and observations that will be collected during the study.

Create the project

1. Create a project

Create a new project and provide the information required to identify the experiment.

2. Define the experimental units

Organize the project around the plots, entries, or other experimental units that will receive observations.

3. Define the traits

Specify which phenotypic variables will be measured and how their values should be recorded.

4. Add collaborators

Give each field collector access to the project before collection begins.

TraitTrack data format

TraitTrack uses a structured project model. At a basic level, an observation connects an experimental unit to a trait and a recorded value.

Field Purpose
Project Identifies the experiment or study.
Plot / entry Identifies the experimental unit being observed.
Trait Identifies what is being measured.
Trait format Defines how the observation is represented, such as numeric, categorical, Boolean, date, scale, location, or media.
Value Contains the actual observation recorded in the field.
Observer Identifies the collaborator who recorded the observation.
Timestamp Records when the observation was collected or modified.
Media / metadata Connects photographs, location information, notes, or other supporting information to the observation.

Supported trait types

Basic

Text, numeric, percentage, angle, Boolean, date, counter, and scale values.

Categorical

Qualitative observations and categorical scoring systems.

Field measurements

Disease ratings, stopwatch measurements, and location/GNSS observations.

Media

Photographs, audio, and video associated with observations.

Identification

Barcode-based identification of field material or experimental units.

Hardware-assisted

Sensor and external-camera workflows where supported by the application.

Best practice: Define trait names, units, scoring scales, and expected formats before collection starts. Consistent definitions make the resulting dataset much easier to analyze.

Collaborators

TraitTrack is designed for multiple people to collect observations within the same project.

Project owner

Creates and manages the project, configures the experimental structure, and monitors overall collection.

Field collaborators

Use their own iOS devices to collect observations, photographs, notes, and supported measurements.

Shared project state

Collaborators contribute to the same project rather than creating independent datasets for later manual merging.

Important: Collaboration depends on synchronization. A record collected on a device may remain local until the device has connectivity and completes its synchronization cycle.

Using TraitTrack

TraitTrack has two primary uses: managing the project and collecting observations in the field.

Data Management

Data management in TraitTrack covers synchronization, review, project oversight, corrections, and export.

Synchronization

TraitTrack uses near-real-time synchronization rather than instantaneous synchronization. The client initiates a reconciliation cycle at a nominal 30-second interval while the project is active, subject to connectivity and backend response time.

Push

Local observations and project changes are sent to the shared backend.

Reconcile

The backend combines changes and maintains the shared project state.

Pull

Devices retrieve the current reconciled project state.

Review

Project owners can use the resulting project state to monitor progress and identify issues.

Review and quality control

Project owners should review the dataset during collection, not only after the field season. Incomplete areas, questionable observations, synchronization problems, and supporting photographs can be investigated while field access remains available.

Completion

Identify plots, traits, or areas that remain incomplete.

Collaborator activity

Check whether collaborators are contributing and synchronizing their devices.

Observation review

Investigate suspicious or unexpected observations.

Image review

Use provenance-linked photographs to help verify observations.

Corrections and conflicts

Multiple users may contribute to the same project. TraitTrack uses unique record identifiers and explicit update rules to prevent duplicate records when changes are transmitted repeatedly.

When concurrent edits produce a conflict, use the application's conflict-resolution workflow rather than manually combining competing versions in separate files.

Export

Project data can be exported for downstream analysis. TraitTrack supports CSV export and database-oriented workflows, as well as media bundles and project backups.

Recommended workflow: Collect → Synchronize → Review → Quality control → Export → Analyze

Field Data

TraitTrack is designed to make structured phenotypic observations practical to collect directly in the field.

Collect an observation

1. Select the project

Open the project associated with the experiment.

2. Navigate to the experimental unit

Select the appropriate plot, entry, or other experimental unit.

3. Select the trait

Choose the trait being measured.

4. Record the value

Enter the observation using the trait's defined format.

5. Add supporting information

When appropriate, attach photographs, location information, notes, or other supported media.

6. Save and continue

Save the observation and proceed to the next experimental unit.

Working offline

Field sites may have unreliable or nonexistent network connectivity. TraitTrack is designed so that collection can continue when a connection is unavailable, with synchronization occurring when connectivity returns.

Before leaving for the field: Make sure the project information required for collection is available on the device. Do not assume that a device will be able to download project information after you arrive at a location without connectivity.

Photographs and media

Photographs can be attached to observations to preserve visual evidence of the phenotype or field condition. Images can be especially useful for disease scoring, abiotic stress, developmental stages, and quality control.

Location and GNSS

TraitTrack can use iOS Core Location to record GNSS coordinates for location-aware traits. Projects should document how location information is expected to be interpreted and used.

Field data best practices

  • Use consistent trait definitions and units.
  • Confirm that you are recording against the correct experimental unit.
  • Attach photographs when visual evidence will be useful.
  • Synchronize whenever a stable connection is available.
  • Check for incomplete or questionable observations before leaving the field.

Support

If something is not working as expected, first determine whether the problem is related to the device, project access, synchronization, or the observation itself.

Data is not synchronizing

Check the network connection, pending uploads, and synchronization status. Try again when a stable connection is available.

A project is missing

Confirm that you are signed into the correct account and have been added to the project as a collaborator.

An observation is missing

Check the device where the observation was collected and its synchronization status before assuming the record has been lost.

An image is still uploading

Observation synchronization and large media transfers may complete at different times. Check the media transfer state separately.

Conflicting edits

Use the application's conflict-detection and resolution workflow rather than manually merging competing records.

Unexpected behavior

Record the application version, device, project, steps that produced the problem, and any relevant error message.

When reporting a problem

Include enough information for the problem to be reproduced. At minimum, provide the application version, iOS version, device type, project context, what you expected to happen, and what actually happened.

For synchronization problems, also note whether the device was online and whether other collaborators were able to synchronize successfully.
